# منظومة مدرسة الدلنجات الصناعية بنات — الإصدار التأسيسي

واجهة عربية RTL قابلة للربط بقاعدة بيانات PostgreSQL عبر Supabase، مع تسجيل دخول وصلاحيات مدير/موظف، وسجلات العاملين والطالبات والحضور. يحتوي `schema.sql` كذلك على جداول الإجازات والجزاءات والدورات التدريبية والجداول.

## ما الذي يعمل في هذه النسخة؟
- تسجيل دخول بالبريد وكلمة المرور عبر Supabase Auth.
- إنشاء ملف مستخدم تلقائيًا بدور `employee`.
- لوحة إحصائيات أساسية.
- إضافة وعرض بيانات الطالبات والبحث فيها.
- تسجيل حضور/غياب/تأخير/إذن، مع منع تكرار سجل الطالبة في اليوم نفسه.
- إدارة بيانات العاملين من حساب المدير فقط.
- سياسات RLS على الجداول لمنع الوصول غير المصرح به من واجهة الموقع.
- تصميم متجاوب للكمبيوتر والهاتف.

## ملاحظات قبل الاستخدام الفعلي
- هذا مشروع تأسيسي يحتاج إلى ربط Supabase ونشره واختباره؛ ليس رابطًا منشورًا حتى الآن.
- لا تدخل بيانات حقيقية قبل إتمام إعداد Supabase، ومراجعة سياسات الحماية، واختبار الحسابات والصلاحيات.
- لا تضع مفتاح `service_role` في ملفات الموقع مطلقًا. استخدم فقط عنوان المشروع والمفتاح العام `anon` أو `publishable`.
- أضف حسابات المستخدمين يدويًا من لوحة Supabase، أو نفّذ دعوات آمنة؛ لا تفتح التسجيل العام للموظفين دون ضوابط.
- البيانات التعليمية والشخصية حساسة: استخدم كلمات مرور قوية، وقلّل من جمع البيانات، وحدد المسؤولين المخولين، وراجع متطلبات الجهة التعليمية قبل استضافة بيانات حقيقية.

## خطوات النشر المجاني المقترحة

### 1) إنشاء قاعدة البيانات
1. أنشئ مشروعًا في [Supabase](https://supabase.com/) واختر كلمة مرور قوية لقاعدة البيانات.
2. افتح **SQL Editor** داخل المشروع.
3. افتح الملف `schema.sql` وانسخ محتواه كاملًا إلى محرر SQL ثم اضغط **Run**.
4. من **Project Settings → API** أو قسم مفاتيح المشروع، انسخ **Project URL** والمفتاح العام `anon`/`publishable`.
5. افتح `config.js` واستبدل `https://YOUR-PROJECT.supabase.co` بعنوان مشروعك، واستبدل `YOUR_SUPABASE_ANON_OR_PUBLISHABLE_KEY` بالمفتاح العام.

### 2) إنشاء حساب المدير
1. من **Authentication → Users** أنشئ مستخدمًا ببريد المدير وكلمة مرور قوية.
2. بعد إنشائه، افتح **SQL Editor** ونفّذ الأمر التالي بعد استبدال البريد بالبريد الفعلي:

```sql
update public.profiles p
set role = 'admin', full_name = 'مدير المنظومة'
from auth.users u
where p.id = u.id and u.email = 'ADMIN_EMAIL_HERE';
```

3. أنشئ حسابات الموظفين من لوحة Authentication فقط، وتأكد أن أدوارهم `employee` في `public.profiles`.
4. لا تجعل المستخدمين العاديين قادرين على تعديل دورهم. سياسة RLS تمنع ذلك من الواجهة، ويجب أن يظل التحكم في الأدوار للإدارة.

### 3) نشر الواجهة برابط عام مجاني
1. فك ضغط المشروع على جهازك.
2. أنشئ مستودعًا خاصًا (Private) على GitHub وارفع ملفات المشروع بعد تعديل `config.js`. تذكّر أن المفتاح العام ليس سرًا، لكن سياسات قاعدة البيانات هي خط الدفاع الأساسي.
3. افتح [Netlify](https://www.netlify.com/) وأنشئ موقعًا جديدًا من مستودع GitHub، أو استخدم خيار رفع مجلد الموقع إن كان متاحًا في حسابك.
4. اجعل مجلد النشر هو جذر المشروع حيث يوجد `index.html`، ثم انشره. ستحصل على رابط HTTPS مجاني من Netlify.
5. في Supabase Authentication، راجع إعدادات **Site URL / Redirect URLs** وأضف رابط Netlify الخاص بك.

> الخطط المجانية وحدودها قد تتغير، لذلك راجع شروط الخدمات قبل الاعتماد الرسمي. النشر العام يعني أن صفحة الدخول متاحة على الإنترنت، وليس أن بيانات المدرسة عامة؛ يجب أن تبقى الجداول محمية بسياسات RLS.

## اختبار قبول أساسي قبل إدخال البيانات
- جرّب تسجيل الدخول كمدير: يجب أن تظهر شاشة العاملين.
- جرّب تسجيل الدخول كموظف: يجب ألا تظهر شاشة العاملين أو سجلات الإجازات والجزاءات والتدريب والجداول.
- جرّب فتح قاعدة البيانات من جلسة غير مسجلة: يجب ألا تظهر بيانات.
- اختبر منع تكرار كود الطالبة وسجل الحضور في التاريخ نفسه.
- اختبر السياسات من حساب موظف منفصل؛ لا تعتمد على إخفاء الأزرار فقط.
- فعّل المصادقة متعددة العوامل للمدير إن كانت متاحة، وحدد مسؤولًا عن النسخ الاحتياطي ومراجعة الحسابات.

## ملفات المشروع
- `index.html` — واجهة المنظومة.
- `styles.css` — التنسيق المتجاوب.
- `app.js` — تسجيل الدخول والتعامل مع الجداول.
- `config.js` — إعداد اتصال Supabase (يحتاج إلى بيانات مشروعك).
- `schema.sql` — الجداول وسياسات الحماية.
