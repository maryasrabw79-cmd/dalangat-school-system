# منظومة مدرسة الدلنجات الصناعية بنات — حزمة تشغيل أولية

هذه الحزمة تضم واجهة عربية متجاوبة للأقسام التالية: العاملون، الطالبات، الحضور والغياب، الإجازات، التدريب، والجداول. تستخدم Supabase Auth لتسجيل الدخول، وتقرأ الدور من `public.profiles`.

## محتويات الحزمة
- `index.html` — صفحة الدخول ولوحة التحكم.
- `styles.css` — التنسيق العربي المتجاوب.
- `config.js` — عنوان Supabase والمفتاح العام publishable/anon.
- `app.js` — وظائف تسجيل الدخول والقراءة والإضافة.
- `setup.sql` — إضافة الأعمدة والجداول والسياسات اللازمة دون حذف الجداول أو السجلات الموجودة.

## تنبيه مهم قبل التثبيت
1. هذه الحزمة ليست نشرًا تلقائيًا ولا تعدّل GitHub أو Supabase من تلقاء نفسها.
2. خذ نسخة احتياطية من قاعدة البيانات قبل تشغيل `setup.sql`.
3. لا تشغّل أي ملف SQL على قاعدة الإنتاج قبل مراجعة أسماء الأعمدة والأنواع الموجودة؛ قد تحتاج بعض قواعد البيانات القديمة إلى مواءمة بسيطة إذا كانت أعمدة `id` أو `profiles` مختلفة.
4. لا تضع `service_role` أو أي مفتاح سري داخل `config.js` أو GitHub. المفتاح الموجود في هذا الملف هو المفتاح العام الذي سبق استخدامه في إعداد المشروع، ويمكن استبداله بالمفتاح العام الحالي من Supabase.
5. سياسات الأمان في `setup.sql` تسمح للمدير/الإدارة (الأدوار `admin`, `manager`, `principal`) بالإضافة والتعديل والحذف. دور `viewer` للقراءة فقط. دور `employee` محدود افتراضيًا بملف العامل المرتبط في `profiles.employee_id`. اختبر الصلاحيات بحساب تجريبي قبل إدخال بيانات حقيقية.

## الجزء الأول: تجهيز قاعدة البيانات
1. افتح لوحة Supabase الخاصة بمشروع المدرسة.
2. من القائمة اليسرى اختر **SQL Editor**.
3. أنشئ استعلامًا جديدًا.
4. افتح `setup.sql` من هذه الحزمة، وانسخ محتواه كاملًا إلى SQL Editor.
5. قبل الضغط على **Run**، راجع الاستعلام وخذ نسخة احتياطية. هذا السكربت لا يستخدم `DROP TABLE` ولا يحذف سجلات؛ لكنه يضيف أعمدة ويعيد إنشاء السياسات التي تحمل أسماء `school_*` فقط.
6. اضغط **Run**. إذا ظهر خطأ، توقف وانسخ نص الخطأ كاملًا ولا تجرّب تشغيل استعلامات عشوائية.
7. افتح **Table Editor** وتأكد من الجداول: `employees`, `students`, `attendance`, `leaves`, `training_courses`, `staff_schedules`, `profiles`.
8. افتح `profiles` وتأكد أن حساب المدير الموجود له `role = admin`. لا تنشئ حسابًا عامًا للمدير ولا تمنح الدور عبر نموذج تسجيل عام.

## الجزء الثاني: إعداد الواجهة
1. فك ضغط الملف على جهاز الكمبيوتر.
2. افتح `config.js` بمفكرة Windows.
3. تحقق من `supabaseUrl` والمفتاح العام. يجب أن يطابقا مشروع المدرسة نفسه. لا تستخدم مفتاح `service_role` أو secret key.
4. احفظ الملف.

## الجزء الثالث: رفع الملفات إلى GitHub Pages
الموقع الحالي يستخدم المستودع `dalangat-school-system`.

1. افتح المستودع: https://github.com/maryasrabw79-cmd/dalangat-school-system
2. خذ نسخة احتياطية من الملفات الحالية أولًا: افتح كل ملف (`index.html`, `app.js`, `config.js`) ثم **Download raw file** أو احتفظ بنسخة محلية.
3. استبدل ملفات الواجهة الأربعة في جذر المستودع: `index.html`, `app.js`, `styles.css`, `config.js`. يمكن تحرير الملف من زر القلم ثم استبدال محتواه كاملًا، أو استخدام GitHub Desktop إذا كان متاحًا لديك.
4. لا تستبدل `schema.sql` القديم تلقائيًا؛ احتفظ به كمرجع. ملف التعديل لهذه الحزمة هو `setup.sql`.
5. اكتب رسالة حفظ مثل `Add school management screens` ثم اضغط **Commit changes**.
6. انتظر دقيقة أو دقيقتين، ثم افتح: https://maryasrabw79-cmd.github.io/dalangat-school-system/ واضغط `Ctrl+F5`.

## اختبار آمن بعد الرفع
1. سجّل الدخول بحساب المدير الحالي.
2. جرّب أولًا سجلًا تجريبيًا لا يحتوي بيانات شخصية حقيقية في كل قسم.
3. تحقق من ظهور السجل بعد تحديث الصفحة.
4. سجّل الخروج، ثم جرّب حساب `viewer`: يجب أن يستطيع القراءة فقط ولا يظهر له نموذج الحفظ.
5. جرّب حساب `employee` مرتبطًا بـ `profiles.employee_id`، وتأكد من أنه لا يستطيع الاطلاع على بيانات الطالبات أو الإجازات.
6. إذا ظهر خطأ في الحفظ، انسخ نص رسالة الخطأ كما هو. لا تعِد الضغط على حفظ إذا كان السجل قد ظهر بالفعل.

## الأدوار
- `admin`: مدير النظام؛ كل الأقسام وإدارة السجلات.
- `manager` أو `principal`: صلاحيات إدارة المدرسة.
- `viewer`: قراءة فقط.
- `employee`: صلاحية محدودة؛ يحتاج ربط `profiles.employee_id` بمعرّف العامل.

## حدود النسخة الحالية
هذه نسخة تشغيل أساسية: تسجيل الدخول، عرض السجلات وإضافة سجلات. لا تشمل بعد تعديل/حذف السجلات من الواجهة، تصدير Excel/PDF، أو سجل تدقيق تفصيلي. يفضّل عدم استخدامها كمنظومة إنتاجية ببيانات حساسة قبل مراجعة السياسات والصلاحيات واختبارها على حسابات مختلفة.
